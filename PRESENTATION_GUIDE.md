## 2. Project Overview

- **Goal:** Automated building damage assessment from pre- and post-disaster aerial imagery.
- **Disaster:** Southern California wildfire (SoCal fire tiles from xView2-style data).
- **Outputs:** FEMA-aligned damage classes (no-damage, minor, major, destroyed), interactive map dashboard, evaluation metrics.

---

## 3. Data & Preprocessing

- **Dataset:** Pre/post PNG tiles (e.g. `socal-fire_XXXX_pre_disaster.png`, `_post_disaster.png`) plus JSON labels with building polygons and damage subtypes.
- **Preprocessing:** Parse WKT polygons, crop buildings, derive image-level ground truth (most common building damage per image).
- **Labels:** No damage, minor damage, major damage, destroyed (and un-classified where applicable).

---

## 4. Vision-Language Model (VLM) Pipeline

- **Model:** GPT-4o Vision (OpenAI API).
- **Input:** Cropped pre- and post-disaster building images.
- **Output:** Single label per building; image-level label = worst damage across buildings (FEMA standard).
- **Scripts:** `backend/vlm_pipeline.py` (single pair), `backend/batch_evaluate.py` (batch → results.csv).

---

## 5. ResNet Baseline

- **Architecture:** ResNet-18, 6-channel input (pre + post concatenated), 4-class output.
- **Training:** `backend/train_classifier.py` — 80/20 train/val, ImageNet normalization, optional augmentation.
- **Inference:** `backend/resnet_inference.py` (single pair), `backend/batch_evaluate_resnet.py` (batch, same CSV format as VLM).
- **Note:** 1 epoch = fast demo; 10+ epochs = better accuracy and less variation.

---

## 6. Evaluation Pipeline

- **Metrics:** `evaluation/metrics.py` — accuracy, classification report, confusion matrix (saved as PNG).
- **Extended:** `evaluation/evaluation.py` — per-disaster breakdown, F1 table, regression check.
- **Input:** `evaluation/results.csv` (columns: image_name, vlm_prediction, ground_truth). Generated by either VLM or ResNet batch scripts.

---

## 7. Geospatial Dashboard

- **Stack:** React, Vite, Leaflet, OpenStreetMap base tiles.
- **Data:** `frontend/public/data/` — available images list, house conditions sample; label JSONs for transforms and polygons.
- **Features:**
  - General map view (pan, zoom, bounds fit to SoCal fire tiles).
  - Before/After toggle for pre vs post imagery layers.
  - House boundaries/polygons from labels, color-coded by damage; tooltips.

## 10. Talking Points (Short)

- **Why two models?** VLM for zero-shot reasoning; ResNet for a fast, local baseline and comparison.
- **Why separate train/val (and test)?** Proper evaluation and avoiding overfitting; we use val for model selection and can report final metrics on a held-out test set.
- **Why 1 epoch in the demo?** So training finishes quickly during the presentation; for real results we use 10+ epochs (lower error, less variation).
- **Chat error in UI?** Backend for the chatbot is planned post-midterm; the rubric doesn’t require it.
